# Engineering rules

- Keep question clarification logic in `src/question-guidance.js` so semantic uncertainty behavior is testable without a browser.
- Derive the feasibility-first summary from deterministic plan results in `src/feasibility.js`; never create a second regulatory engine.
- Treat Newton building year and legal lot-creation date as separate facts; never infer one from the other.
- Human review items and incidents live only in the private repo danielk-droid/hpp-governance-private — the main repo is public, so it keeps IDs only.

- Planning guides under `/guides/` are static HTML generated by `scripts/generate-guides.py` (also writes `sitemap.xml`); edit the script and re-run, never hand-edit output. Why: keeps Newton claims tied to `data/sources.json` and the sitemap in sync.
- Question navigation lives in src/question-flow.js: forward goes to the first unanswered step, Back retraces completed-step history, and only questions shown solely for a parent's "unsure" are inline clarifiers — keeps one source of truth so answered questions are never re-asked.
- "I'm not sure" opens exactly one follow-up per question, defined as data in src/unsure-followups.js; it has no "not sure" option, every option maps to a definite parent answer, and it hides once answered. The UI and tests share flow.applyFollowUps — keeps the interaction single-step and deterministic.
